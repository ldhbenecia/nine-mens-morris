# 코드 주석

주석은 다음에 이 코드를 읽고 고칠 사람을 위한 것

## 무엇을 쓰나

**코드만 봐서는 알 수 없는 것만**

- 왜 이렇게 했는지 — 다른 방법을 쓰면 무엇이 깨지는지
- 지켜야 하는 조건 — 순서, 같이 바꿔야 하는 곳, 락 안에서만 불러야 하는 것
- 도메인 규칙 — 밀 보호 예외, 3회 반복·50수 무승부, 비로그인 계정은 랭킹·전적 제외 등

## 쓰지 않는 것

- 코드를 한국어로 다시 읽어 주는 설명
- 개발 과정 이야기 (`기존에는 ~였다`, `예전에는 ~해서`, 조사 경위, 이전 구현 비교) — 커밋·PR·ADR 에
- 문서 경로·번호 (`docs/plans/...`, `ADR-12`, `P0-3`) — 문서는 옮겨지고 번호는 바뀜

## 형식

- 한두 줄, 명사형 종결(`~함`, `~됨`), 끝 마침표 X
- Javadoc(`/** */`) 쓰지 않음. `//` 로 통일
- 필드·상수 설명은 그 줄 끝 `//` 로

```java
// ✅
private static final int MIN_RATED_MOVES = 10;  // 이보다 짧은 판은 레이팅 미반영

// ✅
// 방 단위 락 안에서만 호출. 밖에서 읽으면 이동 중간의 판이 복제될 수 있음
public Optional<RoomEvent> snapshot(long roomId, long actorId) { ... }

// ✅
// 상대 돌이 전부 밀에 속하면 밀 안의 돌도 제거 가능. 없으면 제거 대상이 없어 게임이 멈춤
if (board.isInMill(at) && !board.allStonesInMill(opponent)) { ... }

// ❌ 코드를 다시 읽어 줌
// 사용자를 찾아서 없으면 예외를 던진다

// ❌ 개발 과정
// 기존에는 HashMap 11개에 흩어져 있었다

// ❌ 문서 번호
// ADR-13 참조
```

## 기존 코드

이 규칙 이전에 쓴 주석에는 `기존에는 ~` 형태가 많다.
**일괄 수정하지 않는다.** 그 파일을 다른 이유로 고칠 때 손대는 범위 안에서만 맞춘다
